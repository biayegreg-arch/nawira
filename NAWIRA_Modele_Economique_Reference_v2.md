# NAWIRA — Modèle économique de référence v2

## 0. Statut du document

**Document :** Modèle économique de référence NAWIRA v2  
**Produit :** NAWIRA  
**Format produit :** Web App / PWA responsive, mobile-first  
**Positionnement :** plateforme de santé féminine et de bien-être pensée pour les femmes francophones, avec une forte adaptation aux réalités africaines  
**Signature :** *Comprends ton corps. Vis ta vie sereinement.*  
**Version :** v2  
**Objectif :** définir le modèle économique, les règles de monétisation, les moteurs de rétention, les métriques, les garde-fous et les conditions de passage à l’échelle de NAWIRA.

---

# 1. Vision économique

NAWIRA ne doit pas être conçu comme un simple calendrier menstruel monétisé par un abonnement.

Le modèle de référence est :

> **Free Forever + valeur accumulée + conversion contextuelle + extension progressive sur les étapes de vie féminines.**

Le produit gratuit crée l’habitude, l’historique et la confiance.

Le Premium monétise principalement :

- la compréhension approfondie ;
- la personnalisation ;
- les analyses ;
- l’accompagnement ;
- les parcours à forte intention, notamment Projet Bébé.

La stratégie économique repose sur cinq principes :

1. **Créer une vraie valeur gratuite avant de monétiser.**
2. **Faire augmenter la valeur du produit avec l’historique.**
3. **Proposer le Premium au moment où sa valeur devient visible.**
4. **Maintenir des coûts variables extrêmement faibles sur le Free.**
5. **Transformer les changements d’étape de vie en transitions produit plutôt qu’en churn.**

---

# 2. Architecture du modèle

NAWIRA repose sur trois niveaux commerciaux principaux.

| Offre | Prix de référence | Rôle économique |
|---|---:|---|
| NAWIRA Gratuit | 0 FCFA | Acquisition, activation, habitude, rétention, volume |
| NAWIRA Plus | 1 000 FCFA/mois | Monétisation de la compréhension approfondie |
| Projet Bébé | 2 500 FCFA/mois | Monétisation d’un besoin à forte intention |

Les prix ci-dessus sont les prix de référence actuels. Ils doivent être validés par expérimentation réelle avant toute conclusion définitive.

---

# 3. Philosophie du Freemium

NAWIRA Gratuit est permanent.

Il ne doit pas fonctionner comme :

> « 3 mois gratuits puis obligation de payer. »

Il fonctionne comme :

> **« Plus tu utilises NAWIRA, plus la plateforme peut t’aider à comprendre tes propres tendances. »**

Le gratuit doit être suffisamment utile pour :

- attirer ;
- activer ;
- fidéliser ;
- créer de la confiance ;
- générer des recommandations ;
- nourrir les futures conversions Premium.

Le Premium ne doit pas supprimer artificiellement une valeur déjà acquise. Il doit débloquer une valeur supplémentaire.

---

# 4. Principe des 3 cycles

Les trois premiers cycles constituent un jalon stratégique majeur.

Ils permettent de passer progressivement de :

**données isolées → historique → comparaison → tendances → personnalisation.**

Le parcours de base est :

| Étape | Expérience | Objectif |
|---|---|---|
| Cycle 1 | Gratuit | Découverte et première valeur |
| Cycle 2 | Gratuit | Comparaison et engagement |
| Cycle 3 | Gratuit | Apparition de tendances |
| Après 3 cycles | Gratuit maintenu + offre contextuelle | Conversion |
| Plus | Premium | Analyses approfondies |
| Projet Bébé | Premium spécialisé | Parcours fertilité avancé |

Cependant, les trois cycles ne sont pas une règle rigide.

NAWIRA doit convertir en fonction de :

- la valeur accumulée ;
- l’intention ;
- le niveau d’engagement ;
- le contexte d’usage ;
- le type de besoin.

---

# 5. Conversion contextuelle

Le paywall ne doit pas être déclenché uniquement par le temps.

NAWIRA doit utiliser plusieurs signaux :

- nombre de cycles enregistrés ;
- fréquence d’utilisation ;
- quantité de symptômes enregistrés ;
- consultation répétée d’analyses ;
- activation du Projet Bébé ;
- demande d’une fonctionnalité Premium ;
- niveau d’historique disponible.

Le principe est :

> **Bon moment + bonne fonctionnalité + bonne utilisatrice = meilleure conversion.**

---

# 6. Value Score interne

NAWIRA peut utiliser un score interne invisible à l’utilisatrice pour détecter les moments de conversion.

Exemple de logique :

| Action | Signal possible |
|---|---:|
| Premier cycle enregistré | +20 |
| Symptômes enregistrés plusieurs fois | +10 |
| Calendrier consulté régulièrement | +5 |
| Deuxième cycle enregistré | +20 |
| Analyse consultée | +10 |
| Troisième cycle enregistré | +25 |
| Projet Bébé activé | signal spécifique |
| Interaction répétée avec fonctionnalité Premium | signal fort |

Ce score ne doit jamais devenir un outil de manipulation.

Il sert uniquement à éviter des paywalls mal placés.

# 11. Activation

L’activation doit être rapide.

L’utilisatrice doit recevoir une première valeur en quelques minutes.

Objectif :

> **Time to First Value minimal.**

Première valeur possible :

- jour du cycle ;
- prochaine période estimée ;
- fenêtre fertile estimée ;
- insight simple ;
- premier calendrier personnalisé.

L’onboarding doit rester court et progressif.

---

# 12. Rétention

NAWIRA ne doit pas chercher artificiellement une utilisation quotidienne.

La vraie question est :

> **L’utilisatrice revient-elle au cycle suivant ?**

Les principaux moteurs de rétention sont :

- historique ;
- comparaison ;
- personnalisation ;
- notifications utiles ;
- rapports ;
- Projet Bébé ;
- continuité de vie.

---

# 13. North Star Metric

La métrique principale proposée est :

> **Nombre d’utilisatrices actives ayant enregistré au moins 3 cycles utiles.**

Pourquoi :

- elle mesure l’activation ;
- elle mesure la répétition ;
- elle mesure la création d’historique ;
- elle précède la personnalisation ;
- elle est corrélée au potentiel de conversion.

---

# 14. Cycle Completion Rate

NAWIRA doit suivre :

> **% des utilisatrices du cycle N qui enregistrent le cycle N+1.**

Exemple :

- Cycle 1 : 10 000
- Cycle 2 : 6 500
- Cycle 3 : 4 500
- Cycle 4 : 3 800

Cette métrique permet d’identifier les pertes de rétention avec beaucoup plus de précision qu’un simple MAU.

---

# 15. Cohortes

Toutes les métriques majeures doivent être analysées par cohortes.

Exemples :

- mois d’inscription ;
- pays ;
- tranche d’âge ;
- objectif Cycle ;
- objectif Projet Bébé ;
- canal d’acquisition ;
- plan ;
- engagement initial.

Il ne faut jamais dépendre d’une moyenne globale qui masque les meilleurs ou pires segments.

# 16. Unit Economics

NAWIRA doit piloter les métriques économiques suivantes.

## 16.1 MRR

**Monthly Recurring Revenue**

## 16.2 ARR

**Annual Recurring Revenue**

## 16.3 ARPU

**Average Revenue Per User**

## 16.4 CAC

**Customer Acquisition Cost**

## 16.5 LTV

**Lifetime Value**

## 16.6 LTV/CAC

## 16.7 CAC Payback

Mesure du nombre de mois nécessaires pour récupérer le coût d’acquisition.

---

# 17. Free Cost per MAU

NAWIRA doit officiellement suivre :

> **Free Cost per MAU = coûts variables des utilisatrices Free ÷ MAU Free**

Ce KPI est critique.

Il inclut notamment :

- infrastructure ;
- stockage ;
- notifications ;
- services tiers ;
- support variable ;
- traitements ;
- éventuelle IA.

Objectif :

> **maintenir le Free extrêmement peu coûteux.**

---

# 18. Contribution Margin

Le revenu ne suffit pas.

NAWIRA doit suivre :

**Revenu**

− frais de paiement

− infrastructure

− IA

− notifications

− support variable

− autres coûts directement liés à l’usage

= **marge de contribution**

La marge de contribution doit guider les décisions de scale.

---

# 19. Revenue per 1,000 MAU

KPI recommandé :

> **R1K = revenu mensuel généré par 1 000 MAU.**

Avec l’hypothèse :

- 5 % Plus ;
- 3 % Projet Bébé ;

1 000 MAU donnent :

- 50 Plus × 1 000 = 50 000 FCFA ;
- 30 Projet Bébé × 2 500 = 75 000 FCFA.

Soit :

> **125 000 FCFA / 1 000 MAU / mois**

Cette métrique doit être comparée au coût de service de 1 000 MAU.

# 20. Scénarios financiers

Les conversions ne doivent jamais être considérées comme acquises.

| Scénario | Plus | Projet Bébé | Total payant |
|---|---:|---:|---:|
| Défensif | 2 % | 1 % | 3 % |
| Cible | 5 % | 3 % | 8 % |
| Fort | 8 % | 5 % | 13 % |

## Exemple à 100 000 MAU

### Scénario défensif

- 2 000 Plus = 2 M FCFA
- 1 000 Projet Bébé = 2,5 M FCFA

**MRR : 4,5 M FCFA**

### Scénario cible

- 5 000 Plus = 5 M FCFA
- 3 000 Projet Bébé = 7,5 M FCFA

**MRR : 12,5 M FCFA**

### Scénario fort

- 8 000 Plus = 8 M FCFA
- 5 000 Projet Bébé = 12,5 M FCFA

**MRR : 20,5 M FCFA**

# 21. Churn

Le churn Premium doit être surveillé séparément pour :

- Plus ;
- Projet Bébé ;
- pays ;
- cohorte ;
- canal.

Projet Bébé possède un churn naturel lié aux changements d’étape de vie.

La stratégie est donc :

> **ne pas considérer la fin d’un besoin comme la fin de la relation.**

# 22. Life-Stage Expansion

Vision long terme :

**Cycle → Projet Bébé → Grossesse → Post-partum → Retour du cycle → Bien-être féminin → Périménopause/Ménopause.**

Cette extension n’est pas le MVP.

Elle représente la stratégie de longévité de la LTV.

Chaque nouvelle étape doit être développée uniquement si :

- le besoin est validé ;
- la rétention existe ;
- le modèle économique principal fonctionne.

# 31. Confidentialité comme avantage concurrentiel

Principes publics :

> **Tes données t’appartiennent.**

> **NAWIRA ne vend pas tes données menstruelles.**

> **Tu peux exporter et supprimer tes données.**

---

# 32. Privacy by Design

NAWIRA doit :

- collecter uniquement les données nécessaires ;
- limiter les accès ;
- chiffrer les données sensibles ;
- gérer les consentements ;
- permettre export et suppression ;
- journaliser les accès administratifs ;
- éviter les SDK publicitaires sur données de santé ;
- séparer autant que possible identité et données sensibles ;
- minimiser les données transmises aux tiers.

---

# 33. Medical Safety Layer

Chaque fonctionnalité doit être classée.

| Niveau | Exemple |
|---|---|
| Éducatif | « Qu’est-ce que la LH ? » |
| Personnel non diagnostique | « Tu as enregistré ce symptôme plusieurs fois » |
| Estimation | « Ovulation estimée autour du… » |
| Orientation prudente | « Ces symptômes persistants méritent un avis professionnel » |
| Interdit | diagnostic, prescription, garantie |

> **Free Forever + valeur accumulée + conversion contextuelle + Premium spécialisé + contrôle strict des coûts + forte confiance + croissance conditionnée par les unit economics.**

Le succès de NAWIRA ne dépendra pas du nombre de fonctionnalités.

Il dépendra de la capacité à :

- créer une première valeur rapidement ;
- faire revenir les utilisatrices sur plusieurs cycles ;
- transformer l’historique en compréhension ;
- convertir sans dégrader la confiance ;
- maintenir un Free peu coûteux ;
- monétiser efficacement Plus et Projet Bébé ;
- réduire structurellement le CAC ;
- protéger les données ;
- rester prudent médicalement ;
- prolonger la relation à travers les différentes étapes de vie ;
- ne scaler qu’après preuve de rentabilité.

La priorité n’est donc pas :

> **« construire le maximum »**

mais :

> **« prouver la valeur, la rétention, la confiance et l’économie avant d’accélérer. »**
