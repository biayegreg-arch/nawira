# E4 Part 1 — PWA Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make NAWIRA installable (Web App Manifest + service worker) with a cached app shell for faster repeat loads and an honest offline fallback screen — zero offline data reads or writes in this pass.

**Architecture:** A Next.js-native `manifest.ts` route, 3 placeholder PNG icons generated once via `next/og` and committed as static assets, a hand-written plain-JS service worker (`public/sw.js`, no Workbox/`next-pwa`) that caches static assets and page shells opportunistically (never `/api/*`), a dedicated `/offline` fallback page, and two small client components (`PwaRegister` + `ServiceWorkerUpdateBanner`) wired into the root layout for registration and controlled updates.

**Tech Stack:** Next.js 16 App Router (`manifest.ts`, `next/og`'s `ImageResponse`), plain-JS Service Worker API (Cache Storage), React 19 client components, `tsx` (already a devDependency) for the one-time icon script.

**Spec:** `docs/superpowers/specs/2026-09-17-e4-pwa-shell-design.md`

## Global Constraints

- Client-only. No Prisma schema changes, no migration, no new API routes.
- Icon generation uses `next/og`'s `ImageResponse` (ships with Next.js — zero new dependency). The script runs once during implementation; its PNG output is committed as static files under `frontend/public/icons/` — it is NOT part of the build or request pipeline.
- The service worker (`frontend/public/sw.js`) is hand-written plain JavaScript — no Workbox, no `next-pwa`/`@ducanh2912/next-pwa`, no build-time precache manifest. It explicitly passes through every `/api/*` request and every non-`GET` request untouched — it must never intercept these.
- **Deviation from spec §8 (testing), decided during planning:** this codebase has ZERO existing React-component-testing infrastructure — `frontend/vitest.config.ts`'s `include` glob only matches `src/**/*.test.ts` (not `.test.tsx`), `environment` is `'node'` globally (no jsdom), and no `@testing-library/react`/`jsdom` dependency exists anywhere in `package.json`. The spec assumed `ServiceWorkerUpdateBanner` would get "a normal Vitest/Testing-Library component test," but adding that whole testing stack (new deps, environment reconfiguration) for one ~20-line banner is disproportionate scope creep this plan does not take on. `ServiceWorkerUpdateBanner.tsx`, `PwaRegister.tsx`, and `public/sw.js` all get ZERO automated tests — all three are verified together in Task 5's manual browser pass. Flag this to the user when the plan completes; they may want the testing infrastructure added as a separate, deliberate decision later.
- Real color values verified against `frontend/src/app/globals.css` for this plan: `--color-background: #fdfbfd` (line 13), `--color-primary: #6c43c1` (line 22) — the manifest's `background_color`/`theme_color` below use these exact values.
- `frontend/src/app/layout.tsx`'s current exact structure (verified before writing Task 4) wraps `{children}` as `<ToastProvider><AuthProvider>{children}</AuthProvider></ToastProvider>` inside `<body className={dmSans.className}>` inside `<html lang="fr" className={dmSans.variable}>` — Task 4 adds `<PwaRegister />` as a sibling to `<ToastProvider>`, not nested inside it (matches the spec's "mounts once for the whole app" intent; `ToastProvider`'s own toast overlay already renders this way — as a sibling to `{children}`, not wrapping it more deeply than needed).
- Icons are an explicitly-labeled placeholder (violet `#6C43C1` background + a droplet symbol, matching the existing sidebar's `lucide-react` `Droplet` icon) — a code comment in the generation script must say so, since no real NAWIRA brand icon asset exists anywhere in this repo today.

Create `frontend/scripts/generate-pwa-icons.tsx`:

```tsx
// Explicit React import required here: this file runs standalone via
// `tsx` (esbuild's classic JSX transform, since tsconfig.json's
// `"jsx": "preserve"` is meant for Next's own SWC bundler, not esbuild)
// — without it, `React.createElement` is undefined at runtime and the
// script throws `ReferenceError: React is not defined`. Verified by
// running this exact script standalone before finalizing this plan.
import React from 'react';
import { ImageResponse } from 'next/og';
import { writeFileSync, mkdirSync } from 'node:fs';
import { join } from 'node:path';

const OUT_DIR = join(process.cwd(), 'public/icons');

interface IconSpec {
  file: string;
  size: number;
  /** Maskable icons need ~10% safe-zone padding so OS icon masks don't clip the symbol. */
  padding: number;
}

const ICONS: IconSpec[] = [
  { file: 'icon-192.png', size: 192, padding: 0 },
  { file: 'icon-512.png', size: 512, padding: 0 },
  { file: 'icon-512-maskable.png', size: 512, padding: 51 }, // ~10% of 512
];

async function main(): Promise<void> {
  mkdirSync(OUT_DIR, { recursive: true });
  for (const icon of ICONS) {
    const inner = icon.size - icon.padding * 2;
    const response = new ImageResponse(
      (
        <div
          style={{
            width: '100%',
            height: '100%',
            display: 'flex',
            alignItems: 'center',
            justifyContent: 'center',
            background: '#6c43c1',
          }}
        >
          <div
            style={{
              width: inner,
              height: inner,
              display: 'flex',
              alignItems: 'center',
              justifyContent: 'center',
            }}
          >
            {/* Droplet symbol — matches the existing sidebar branding
                (frontend/src/components/app/AppSidebar.tsx uses
                lucide-react's Droplet icon). PLACEHOLDER: replace with a
                real brand asset before public launch. */}
            <svg width={inner} height={inner} viewBox="0 0 24 24" fill="#ffffff">
              <path d="M12 2C12 2 5 10.5 5 15a7 7 0 0 0 14 0c0-4.5-7-13-7-13z" />
            </svg>
          </div>
        </div>
      ),
      { width: icon.size, height: icon.size },
    );
    const buffer = Buffer.from(await response.arrayBuffer());
    writeFileSync(join(OUT_DIR, icon.file), buffer);
    console.log(`wrote ${icon.file}`);
  }
}

main().catch((err) => {
  console.error(err);
  process.exit(1);
});
```

### Task 3: Service worker

**Files:**
- Create: `frontend/public/sw.js`

**Interfaces:**
- Consumes: the `/offline` route from Task 1 (precached at `install`, must exist).
- Produces: `self.addEventListener('fetch', ...)` behavior that Task 4's `PwaRegister.tsx` registers via `navigator.serviceWorker.register('/sw.js')`, and a `message` listener expecting `{ type: 'SKIP_WAITING' }` that Task 4's banner posts to trigger an update.

Plain JavaScript, served directly from `public/` with no build step — this file is NOT compiled by Next.js or Vitest. No automated test (see Global Constraints); verification here is a syntax check only, with full behavioral verification deferred to Task 5.

- [ ] **Step 1: Write the service worker**

Create `frontend/public/sw.js`:

```js
const CACHE_NAME = 'nawira-shell-v1';
const OFFLINE_URL = '/offline';

self.addEventListener('install', (event) => {
  event.waitUntil(caches.open(CACHE_NAME).then((cache) => cache.add(OFFLINE_URL)));
});

self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches
      .keys()
      .then((keys) => Promise.all(keys.filter((k) => k !== CACHE_NAME).map((k) => caches.delete(k)))),
  );
  self.clients.claim();
});

self.addEventListener('message', (event) => {
  if (event.data && event.data.type === 'SKIP_WAITING') self.skipWaiting();
});

function isStaticAsset(url) {
  return url.pathname.startsWith('/_next/static/');
}

self.addEventListener('fetch', (event) => {
  const url = new URL(event.request.url);

  // Never intercept API calls — no offline data reads in this pass, and
  // this must not interfere with CSRF/refresh handling in lib/api.ts.
  if (url.pathname.startsWith('/api/')) return;
  if (event.request.method !== 'GET') return;

  if (isStaticAsset(url)) {
    event.respondWith(
      caches.match(event.request).then(
        (cached) =>
          cached ||
          fetch(event.request).then((response) => {
            const clone = response.clone();
            caches.open(CACHE_NAME).then((cache) => cache.put(event.request, clone));
            return response;
          }),
      ),
    );
    return;
  }

  if (event.request.mode === 'navigate') {
    event.respondWith(
      fetch(event.request)
        .then((response) => {
          const clone = response.clone();
          caches.open(CACHE_NAME).then((cache) => cache.put(event.request, clone));
          return response;
        })
        .catch(() => caches.match(event.request).then((cached) => cached || caches.match(OFFLINE_URL))),
    );
  }
});
```

- [ ] **Step 2: Write the registration component**

Create `frontend/src/components/pwa/PwaRegister.tsx`:

```tsx
'use client';

import { useEffect, useState } from 'react';
import { ServiceWorkerUpdateBanner } from './ServiceWorkerUpdateBanner';

export function PwaRegister(): React.JSX.Element | null {
  const [waitingWorker, setWaitingWorker] = useState<ServiceWorker | null>(null);

  useEffect(() => {
    if (!('serviceWorker' in navigator)) return;

    navigator.serviceWorker.register('/sw.js').then((registration) => {
      if (registration.waiting) setWaitingWorker(registration.waiting);

      registration.addEventListener('updatefound', () => {
        const newWorker = registration.installing;
        if (!newWorker) return;
        newWorker.addEventListener('statechange', () => {
          if (newWorker.state === 'installed' && navigator.serviceWorker.controller) {
            setWaitingWorker(newWorker);
          }
        });
      });
    });

    let reloaded = false;
    navigator.serviceWorker.addEventListener('controllerchange', () => {
      if (reloaded) return;
      reloaded = true;
      window.location.reload();
    });
  }, []);

  if (!waitingWorker) return null;

  return (
    <ServiceWorkerUpdateBanner
      onReload={() => waitingWorker.postMessage({ type: 'SKIP_WAITING' })}
    />
  );
}
```
