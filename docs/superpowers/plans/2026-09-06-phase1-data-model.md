# Phase 1 — NAWIRA Core Data Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the Prisma schema for NAWIRA's cycle-tracking domain (Profile, Consent, PeriodEvent, Cycle, DailyLog, SymptomLog, FertilitySignal, Prediction, Insight) so Phase 2 (onboarding) and Phase 3 (cycle/fertility engine) have a data model to build on.

**Architecture:** One Prisma schema addition + one versioned migration, following this repo's existing precedent of bundling a phase's related models into a single migration (see `prisma/migrations/4_phase3_admin_orders`, which bundles `Order`+`Withdrawal`+`AdminAction` fields in one migration rather than one per model). No application code (routes, Zod schemas, business logic) is added in this plan — that's Phase 2/3.

**Tech Stack:** Prisma 5, PostgreSQL (Neon), no new runtime dependencies.

**Spec:** [docs/superpowers/specs/2026-09-06-phase1-data-model-design.md](../specs/2026-09-06-phase1-data-model-design.md)

## Global Constraints

- **No native Prisma `enum` blocks.** This schema has zero of them — `User.role`, `User.status`, `Order.status` etc. are all `String` columns with `@default(...)` and an inline `// VALUE_A | VALUE_B` comment, validated at the Zod/route layer. Every enum-like column in this plan follows that exact pattern.
- **Every new domain model is user-owned** (`userId String` referencing `User.id`, `onDelete: Cascade`) — no multi-tenancy, no org-scoping. Supports future account-deletion (§12 of the PRD requires export/delete) by letting a single `User` delete cascade cleanly.
- **Do not rename or restructure existing models.** Only add new models and new relation fields on `User`.
- **Money/units:** not applicable to this phase (no payment amounts touched).
- **Minimum age 18+** is enforced at the application layer in Phase 2 (signup/onboarding), not by a schema constraint — `Profile.birthDate` just stores the value Phase 2 validates against.
- Must keep `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, and the full `pnpm test` suite (570+ existing tests) green throughout — this plan adds zero application code, so zero existing tests should need changes.

```prisma
// ───────────────────────────────────────────────────────────────────────
// NAWIRA Phase 1 — cycle-tracking domain models.
// See docs/superpowers/specs/2026-09-06-phase1-data-model-design.md for
// the full rationale (PRD section references, why Cycle/Prediction are
// materialized rather than computed on read, why enums are plain String
// columns matching the rest of this schema).
// ───────────────────────────────────────────────────────────────────────

model Profile {
  userId            String   @id
  user              User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  birthDate         DateTime
  goal              String // PERIOD_TRACKING | UNDERSTAND_CYCLE | TRYING_TO_CONCEIVE
  usualCycleLength  Int?
  usualPeriodLength Int?
  trackedConcerns   String[] @default([])
  plan              String   @default("FREE") // FREE | PLUS | BABY
  temperatureUnit   String   @default("CELSIUS") // CELSIUS | FAHRENHEIT
  createdAt         DateTime @default(now())
  updatedAt         DateTime @updatedAt
}

model Consent {
  id        String    @id @default(cuid())
  userId    String
  user      User      @relation(fields: [userId], references: [id], onDelete: Cascade)
  type      String // ACCOUNT | HEALTH_DATA | ASSISTANT_HISTORY | NOTIFICATIONS | ANALYTICS | MARKETING
  version   Int
  grantedAt DateTime  @default(now())
  revokedAt DateTime?

  @@index([userId, type])
}
```
